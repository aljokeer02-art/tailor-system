# مِقياس — نظام إدارة محل الخياطة الرجالية

نظام ويب متكامل لإدارة محل خياطة رجالية: العملاء والمقاسات، أوراق العمل وتتبع مراحل
الإنتاج، المخزون (أقمشة ومستلزمات)، العمال وحساب الأجور بالقطعة، التقارير المالية،
تسجيل دخول متعدد المستخدمين بالصلاحيات، والفوترة الإلكترونية المبسطة (ZATCA - المرحلة الثانية).

## المتطلبات
- Node.js نسخة 18 أو أحدث (نزّله من https://nodejs.org إن لم يكن مثبتاً)
- حساب Supabase مجاني (لقاعدة البيانات) — https://supabase.com
- حساب Vercel مجاني (للنشر) — https://vercel.com

النظام الآن يستخدم **PostgreSQL عبر Supabase** كقاعدة بيانات دائمة (بدلاً من ملف
SQLite محلي)، بحيث لا تُفقد بياناتك أبداً بغض النظر عن المنصة التي تستضيف عليها
الكود، ويمكن الوصول لها من أي مكان.

## إعداد قاعدة البيانات (مرة واحدة فقط)

1. أنشئ حساباً على https://supabase.com (يمكن استخدام بريدك `alsaadamr94@gmail.com`).
2. أنشئ مشروعاً جديداً (New Project) — اختر اسماً وكلمة مرور لقاعدة البيانات
   (احفظها، ستحتاجها الآن).
3. من داخل المشروع: **Project Settings ← Database ← Connection string** →
   اختر تبويب **URI** وانسخ الرابط الكامل (يبدأ بـ `postgresql://postgres:...`).
4. استبدل `[YOUR-PASSWORD]` في الرابط بكلمة المرور التي اخترتها في الخطوة 2.
   هذا الرابط هو قيمة `DATABASE_URL` التي ستحتاجها في كل الخطوات التالية.

> لا تحتاج إنشاء أي جداول يدوياً — النظام ينشئها تلقائياً في أول تشغيل.

## طريقة التشغيل محلياً

```bash
npm install
cp .env.example .env
```

افتح ملف `.env` الذي أنشأته وضع فيه قيمة `DATABASE_URL` الحقيقية من الخطوة
السابقة، وغيّر `ADMIN_DEFAULT_PASSWORD` و`JWT_SECRET` لقيم خاصة بك. ثم:

```bash
npm start
```

بعد ظهور الرسالة `✅ نظام إدارة محل الخياطة يعمل على: http://localhost:4000`
افتح المتصفح على الرابط: **http://localhost:4000**

## هيكل المشروع

```
tailor-system/
├── server.js                  ← نقطة التشغيل المحلية فقط (تضيف تقديم الواجهة + الاستماع للمنفذ)
├── app.js                     ← تطبيق Express الأساسي (يُستخدم محلياً وعلى Vercel معاً)
├── api/index.js                ← نقطة دخول Vercel (تصدير نفس تطبيق app.js للعمل كدالة Serverless)
├── db.js                      ← اتصال PostgreSQL/Supabase وتعريف المخطط الكامل
├── vercel.json                ← إعداد توجيه الطلبات على Vercel
├── render.yaml                ← إعداد جاهز للنشر على Render (اختياري، بديل لـ Vercel)
├── .env.example                ← نموذج متغيرات البيئة (انسخه إلى .env محلياً)
├── package.json
├── utils/
│   ├── zatca.js                توليد الفاتورة الإلكترونية (UUID, ICV, PIH, QR/TLV)
│   └── auth.js                 تشفير كلمات المرور وجلسات الدخول (JWT)
├── routes/                    ← نقاط الوصول (API): عملاء، طلبات، مخزون، عمال، تقارير، فواتير، مستخدمون
└── public/                    ← الواجهة (React عبر CDN — بدون خطوة بناء Build)
    ├── index.html
    └── app.js
```

كل شيء الآن في مجلد واحد مسطّح (بدون مجلدات فرعية متداخلة) — هذا يجعل رفع
المشروع لأي منصة استضافة أبسط وأقل عرضة لأخطاء "الملف غير موجود".

## الوحدات المتوفرة في النظام

1. **العملاء والمقاسات**: سجل كامل لكل عميل، مع إمكانية حفظ أكثر من مقاس لنفس
   العميل واستعادته عند أي طلب جديد.
2. **الطلبات وأوراق العمل**: رقم تسلسلي فريد لكل طلب، حساب الدفعة المقدمة
   والمتبقي، وتحديد تاريخ الاستلام المتوقع تلقائياً حسب ضغط العمل الحالي.
3. **تتبع مراحل الإنتاج**: جديد ← قيد القص ← قيد الخياطة ← مرحلة الكوي ← جاهز
   للاستلام ← تم التسليم، مع سجل كامل لكل تغيير وتسجيل "تعديل على ثوب جاهز".
4. **توزيع المهام على العمال**: ربط كل طلب بالعامل المسؤول مع حساب الأجرة
   بالقطعة وتقرير مستحقات كل عامل.
5. **المخزون**: تتبع كمية الأقمشة وخصمها تلقائياً مع كل طلب، بالإضافة
   لمستلزمات الخياطة وتنبيهات عند الانخفاض.
6. **التقارير المالية**: المبيعات، أرباح الأقمشة، ضريبة القيمة المضافة،
   ومستحقات العمال.
7. **بطاقة القياس / كارت المعمل**: شاشة طباعة مخصصة تعرض المقاسات بدون السعر.
8. **تسجيل الدخول والمستخدمون**: راجع القسم التالي.
9. **الفوترة الإلكترونية (ZATCA)**: راجع القسم الخاص بها أدناه.

## التشغيل على الكمبيوتر والجوال معاً (نفس شبكة الواي فاي) — مجاني بالكامل

1. شغّل النظام (`npm start`) على الكمبيوتر الذي سيبقى مفتوحاً (جهاز المحل الرئيسي).
2. اعرف عنوان الشبكة المحلي (IP): على **ويندوز** اكتب `ipconfig` في موجه
   الأوامر وابحث عن `IPv4 Address` (مثال: `192.168.1.15`). على **ماك**:
   إعدادات النظام ← الشبكة، أو `ipconfig getifaddr en0` في Terminal.
3. اسمح لـ Node.js بالمرور عبر جدار الحماية عند أول تشغيل (اختر "السماح").
4. من الجوال أو أي جهاز آخر على **نفس شبكة الواي فاي**، افتح المتصفح واكتب:
   `http://192.168.1.15:4000` (بعنوانك الفعلي).
5. سجّل الدخول بحساب المستخدم الخاص بذلك الجهاز.

> هذا يعمل فقط داخل شبكة المحل. إذا أُغلق الكمبيوتر الرئيسي يتوقف النظام عن الجميع.

## النشر على الإنترنت مجاناً (Supabase + Vercel) — الطريقة الموصى بها

هذا هو الإعداد الحالي للمشروع: **Supabase** لقاعدة البيانات (دائمة، لا تُفقد
بياناتك أبداً)، و**Vercel** لتشغيل الكود (مجاني بالكامل لهذا الحجم من
الاستخدام، بدون بطاقة بنكية).

**خطوات النشر:**

1. تكون قد أنشأت مشروع Supabase بالفعل من قسم "إعداد قاعدة البيانات" أعلاه،
   واستخرجت منه `DATABASE_URL`. إن لم تفعل بعد، ارجع لتلك الخطوات أولاً.
2. ارفع النسخة الحالية من المشروع (بهيكلها الجديد المسطّح) إلى مستودع GitHub
   `tailor-system` نفسه — بنفس طريقة السحب والإفلات المستخدمة سابقاً، لتحلّ
   محل الملفات القديمة.
3. اذهب إلى https://vercel.com وسجّل حساباً (يمكن استخدام بريدك
   `alsaadamr94@gmail.com`) — اربطه بحساب GitHub الخاص بك.
4. من لوحة Vercel: **Add New… → Project** → اختر مستودع `tailor-system`.
5. Vercel يكتشف تلقائياً أنه مشروع Node.js عبر `vercel.json`. لا تغيّر إعدادات
   البناء الافتراضية.
6. قبل الضغط على Deploy، افتح قسم **Environment Variables** وأضف:
   - `DATABASE_URL` = رابط اتصال Supabase الذي استخرجته
   - `ADMIN_EMAIL` = `alsaadamr94@gmail.com`
   - `ADMIN_DEFAULT_PASSWORD` = كلمة مرور قوية من اختيارك
   - `JWT_SECRET` = أي نص عشوائي طويل من اختيارك
7. اضغط **Deploy**. خلال دقيقة تقريباً يعطيك Vercel رابطاً دائماً مثل
   `https://tailor-system.vercel.app` يعمل من أي مكان بالعالم، على الجوال
   والكمبيوتر معاً.
8. سجّل الدخول بالبريد وكلمة المرور اللذين حدّدتهما، ثم غيّرها فوراً وأنشئ
   حساباً لكل موظف من صفحة "المستخدمون".

**لماذا هذا الخيار أفضل من المحاولات السابقة (Render / GoDaddy)؟** لأن
البيانات الآن لا تعيش على قرص السيرفر نفسه بل في قاعدة بيانات Supabase
منفصلة ودائمة — فلا مشكلة إطلاقاً إن كانت خطة الاستضافة "مجانية سيرفرلس"
تُعيد تشغيل السيرفر بين الطلبات، لأن قاعدة البيانات لا علاقة لها بذلك. هذا
أيضاً يعني أن نفس الكود الآن يعمل بنفس الموثوقية على **Render المجاني** (راجع
`render.yaml`) لو أردت بديلاً لـ Vercel لاحقاً — فقط أضف نفس `DATABASE_URL`.

**تحديث لاحق للكود:** أي تعديل تريده مستقبلاً، عدّله محلياً وارفعه لنفس
مستودع GitHub — Vercel ينشر النسخة الجديدة تلقائياً خلال دقيقة.

## الفوترة الإلكترونية (ZATCA) — الوضع الحالي وخطوات الاستكمال

النظام ينفّذ حالياً الجزء البرمجي الداخلي من الفاتورة المبسطة (Simplified Tax
Invoice - B2C):
- **UUID** فريد لكل فاتورة.
- **ICV** عدّاد تسلسلي بدون ثغرات.
- **PIH** تجزئة SHA-256 مرتبطة بالفاتورة السابقة (سلسلة غير قابلة للتعديل).
- **QR Code** بصيغة TLV (Tag-Length-Value) مُحوّل إلى Base64.

للانتقال إلى الربط الفعلي المُعتمد من هيئة الزكاة والضريبة والجمارك، يلزم:

1. **CSID Onboarding**: توليد مفتاح خاص وطلب توثيق (CSR) عبر بوابة فاتورة
   (Fatoora Portal) للحصول على شهادة الاختبار ثم شهادة الإنتاج.
2. **توليد XML بصيغة UBL 2.1** فعلي وتوقيعه رقمياً بالشهادة المستلمة.
3. **الربط مع Reporting API** الرسمي لإرسال ملف XML خلال 24 ساعة من الإصدار.

هذه الخطوات تتطلب حساب فعّال لدى الهيئة ولا يمكن تنفيذها دون بيانات المنشأة
الحقيقية. البنية الحالية (جدولا `invoices` و`shop_settings`) مصممة لتستوعب
هذا الربط دون تعديل جذري.

## ملاحظات تقنية
- الواجهة مبنية بـ React عبر CDN مباشرة (بدون Webpack/Vite) لتشغيل فوري.
- قاعدة البيانات PostgreSQL مُستضافة على Supabase — دائمة ومتاحة من أي مكان،
  ونفس القاعدة تُستخدم محلياً وفي الإنتاج معاً (عبر متغير `DATABASE_URL`).
- **النسخ الاحتياطي**: من لوحة Supabase (Database ← Backups) نسخ احتياطية
  تلقائية يومية على الخطة المجانية لفترة محدودة؛ للأمان الإضافي يمكنك أيضاً
  تصدير نسخة عبر Database ← Backups ← Download، أو تشغيل `pg_dump` بالرابط
  الموجود في `DATABASE_URL` من أي جهاز فيه Postgres مثبت.
- ملفا `server.js` (للتشغيل المحلي) و`api/index.js` (لـ Vercel) كلاهما
  يستخدمان نفس تطبيق `app.js` — أي تعديل على المسارات (routes) ينعكس في
  الحالتين تلقائياً دون ازدواجية في الكود.
